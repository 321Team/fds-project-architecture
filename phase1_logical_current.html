1차 논리 아키텍처 · 정본 반영

교육장 Kubernetes 환경에서 거래 접수·위험 판정·저장과 배포·운영 관리를 연결한 구조입니다.

1차 프로젝트는 조건부 최종 인수·종결되었습니다. 구성 설명과 관측 시점의 시험 결과를 구분하며, 남은 보안·복구 한계를 없어진 것으로 표시하지 않습니다.

경로별 역할과 확인 범위

경로 구성·역할 확인 범위
서비스 진입 nginx HTTP 80 → Worker NodePort 30080 → API Service 80 / Pod 8000 기존 실행 증적을 반영했습니다. 1차 edge HTTPS는 미충족이며, 전체 nginx 정책을 새로 검증한 것은 아닙니다.
거래 처리 API → 탐지 엔진 8001, API → PostgreSQL 5432. 엔진의 DB 직접 접근 차단 2026-10-19 배포 후 두 서비스가 Worker별 1개씩 분산된 관측을 연결합니다. 전 구간 무손실·지속 가용성을 보장하지 않습니다.
클러스터 관리 별도 HAProxy가 TLS를 종료하지 않고 제어 노드 3대의 API 6443으로 전달 서비스 진입용 nginx와 목적이 다릅니다. 기존 백엔드 제외·복귀 검증 범위를 재사용합니다.
이미지 공급 Runner → Harbor push, Worker → Harbor HTTPS pull 기존 검사·전송·배포와 소비처 전환 증적을 연결합니다. 당시 취약점 검사 결과를 현재 DB 기준의 재검사로 해석하지 않습니다.
관측·운영 클러스터 Prometheus·Alertmanager·Grafana, 노드 지표, 별도 외부 Watchdog 10월 19일 11:30:58 KST의 정확한 대상 23/23 관측을 반영합니다. 지속 정상·실패 주입·전체 경보 경로 검증과는 다릅니다.

보안·자동화

기본 통신 차단과 필요한 경로 허용, 역할별 접근권한, 비밀정보 분리, 승인된 Ansible 관리 작업을 적용 대상으로 다룹니다. 부팅 시 보호 전환, 인증정보 회전, 일부 Probe 실패 전이와 전체 자동화 호출 경로의 검증 한계는 유지합니다.

백업·복구

PostgreSQL의 기존 덤프·격리 복원·업무 확인·원복 기록을 연결합니다. 모니터링은 단일 복제본·Worker 3의 로컬 저장소에 의존하므로 다른 노드로 자동 복구된다고 표현하지 않습니다.

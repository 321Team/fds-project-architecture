  1. 주요 트랜잭션 경로 ↗

    외부 HTTPS → IGW → 공개 Ingress LB → OpenShift Router에서 TLS 종료 → transaction-api HTTP 8000 → fds-engine TCP 8001. 외부는 /api·/readyz 두 Route만 공개합니다. Router 이후는 종단간 TLS가 아니며 앱·플랫폼 정책의 합산 허용/차단 검증은 별도입니다.

  2. DB 통신 경로 ↗

    거래 API만 기존 PostgreSQL 5432에 접근합니다. Worker private_a 서브넷 → Relay → IPsec → 교육장 VPN 게이트웨이 → DB 경로와 복귀 경로를 시험창에서 적용·원복합니다. 출발 /24 범위는 앱 정책·DB 인증·실행 증적으로 보완하며 엔진 DB 접근과 VPC 전체 허용은 금지합니다.

  3. IPsec VPN · Hybrid Transit ↗

    교육장 VPN 게이트웨이가 연결을 시작하고 AWS Libreswan Relay가 응답합니다. IKEv2/IPsec UDP 500/4500 NAT-T를 사용하며 터널이 없으면 평문 우회를 차단합니다. 승인된 시험창의 연결·허용/차단·복구 증적은 설계 확정과 별개입니다.

  4. NetworkPolicy (fds-app) ↗

    기본 Ingress/Egress 차단 위에 DNS, Router→거래 API, API→엔진 8001, API→DB 5432의 필요한 경로만 허용하는 설계입니다. probe용 route-exposed 정책과 앱 정책을 구분하고 합산 결과를 확인합니다. Worker의 Harbor 이미지 pull은 Pod NetworkPolicy로 통제했다고 주장하지 않습니다.

  5. CI/CD · 이미지 Pull ↗

    GitHub 작업 → 온프렘 Runner → Harbor 이미지 공급. Runner는 공개 관리 API 443과 제한된 배포 계정으로 Deployment2·Service2·Route2만 변경합니다. Worker는 VPN을 통해 Harbor에서 내려받고, ECR은 검증된 경우 수동 전환합니다. TLS·인증·digest 오류 시 신규 배포를 중단하고 정상 Pod를 보존합니다.

  6. 접근통제 · 모니터링 ↗

    역할별 권한과 restricted-v2 호환 앱 실행을 사용합니다. 배포 계정은 Secret·권한·보안 정책·클러스터 전체를 변경하지 않습니다. 플랫폼 모니터링을 사용하고 UWM은 꺼져 있으며, monitoring-api는 예약 Namespace입니다. 앱 지표 수집은 현재 범위 밖이며 실제 UID·권한 검증은 별도입니다.

적용 기준과 확인 범위

2차 설계 확정

docs-v3.1.22(2026-10-19)의 확정 설계입니다. 단일 가용영역은 Worker 배치 범위이며, 클라우드 통합 검증과 최종 인수는 별도입니다. 이번 변경은 도면의 표현·생성 방식을 통일한 것이며 실제 서버 시험을 새로 수행한 결과가 아닙니다.

3

확정 설계 (논리)

  • Namespace: fds-app · monitoring-api · ci-cd (monitoring-api는 NS·RBAC만, 워크로드 없음)
  • 관리자·조회자·모니터링 담당 권한 분리
  • SCC restricted-v2, custom SCC 없음
  • fds-engine은 DB 직접 접속 없음
4

실환경 검증과 보류 항목

  • 이미지 공급안(Harbor Primary + ECR 수동 전환) Runtime 대기
  • Runner 직접 배포 채택 · API 접속 경로·동작 확인 대기
  • VPN Route ON 전에는 DB·pull 경로 없음
  • 기본 차단·앱 허용 정책은 확정 설계. 실제 합산 정책·허용/거부 검증 별도
  • IPsec 터널·nft 허용표 Runtime 미검증
5

NetworkPolicy (fds-app)

  • NP-00 기본 차단: Ingress·Egress 전부
  • NP-01 DNS: openshift-dns 53/5353만
  • NP-02는 probe용 route-exposed Pod 정책. 앱은 해당 라벨 없이 별도 앱 정책 사용
  • NP-03 onprem-egress API → db01/32 5432. node pull은 Pod 정책과 별도
  • 앱 NP(fds-msa): transaction-api → fds-engine 8001
6

IPsec VPN

  • AWS EC2 Relay 1대 (단일 장애점 위험 유지)
  • vpn-gw01 개시 ⇄ Relay 응답, IKEv2 PSK · UDP 500/4500 NAT-T
  • 터널 대역 10.1.93.0/24 ⇄ 10.20.0.0/16, Route 전파 없음(static)
  • 허용: worker → db01 5432 (+Harbor 443은 이미지 공급안), 온프렘 개시 신규 연결은 차단
  • SA 없으면 drop (평문 우회 차단)
  • Relay는 public 10.20.110.0/24, DB 출발지는 worker private_a 10.20.10.0/24
7

Phase 1 대비

  • kubeadm+Calico → ROSA HCP
  • Prometheus/Grafana 자체 운영 → 플랫폼 모니터링
  • 외부 노출은 /api · /readyz 2개만
  • 진입: IGW → Ingress LB → Router(edge TLS 종료) → Pod

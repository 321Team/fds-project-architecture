# FDS 아키텍처 문서

팀 프로젝트의 서비스 흐름과 설계 범위를 설명하는 정적 HTML 문서입니다. 시작 페이지는 `index.html`, 읽기 안내는 `overview.html`입니다. 설계 채택과 실제 환경 검증·인수 상태를 구분합니다.

## Archify 생성 원본

현행 1·2차 논리도와 물리도 네 개, 각 도면의 읽기 페이지 네 개는 공식 Archify 3.2.0으로 생성합니다. `architecture/*.architecture.json`은 도면 원본, `architecture/*.archify.md`는 설명·단계 원본이며 `diagrams/`에는 독립 대화형 도면을 둡니다. 기존 공개 주소는 유지합니다. 도구 커밋과 검증 경로는 [재생성·검증 안내](architecture/REPRODUCIBILITY.md)를 따릅니다. 생성된 HTML을 직접 수정하지 않습니다.

## 도면 갱신 시 보존할 내용

- 구형 `revision-note`의 의미와 인수·검증 경계는 읽기 페이지의 적용 기준 callout과 도면의 설명 카드에 승계했습니다. `context.css`는 기존 안내·이력 문서를 위해 유지합니다.
- 2차 논리의 17개 노드 ID와 namespace·네트워크 정책 설명을 보존합니다. 기존 6개 안내 ID·설명 전문은 Archify 3.x의 공식 `@steps`로 이전했습니다. 구형 Story/Guided View의 다중 노드 하이라이트·애니메이션과 동일한 기능으로 표현하지 않습니다.
- 사양·상태는 JSON·Markdown 원본에서 수정하고 빌드합니다. 화면 텍스트, 노드 상세, 접근성 속성과 단계 설명을 함께 대조합니다. DB 경로 라벨은 원본 정책 설명에 맞춰 `DB 5432 · NP-03`으로 명확히 했고, 기존 양방향 VPN은 데이터 방향과 IKEv2 개시 방향의 두 관계로 표현했습니다.
- 이전 1차 물리 문서의 커밋 고정 원본 로딩과 `patch()` 마커 검사는 현행 생성 페이지와 별도입니다. 이력 문서의 필수 마커가 없으면 오류를 표시해야 합니다.
- 브라우저에서 문서 목록·개요·도면 안내와 가이드 전환을 확인합니다. 정적 검사나 화면 확인을 서버 Runtime·최종 인수로 기록하지 않습니다.

## 현행 정본과 이력

- 현행 공개 설명: docs-v3.1.22 (2026-10-19). 근거·검증 경계는 `canonical-status.html`에 기록합니다.
- 1차 현행: `phase1_logical_current.html`, `phase1_physical_current.html`. 정본의 구성 기록·후속 관측을 구분해 설명합니다.
- 이전 1차 `logical_architecture.html`, `physical_architecture.html`은 변경 없이 이력으로 보존합니다.
- 2차는 기존 노드 ID·안내 ID와 연결 의미를 보존합니다. Archify 재생성 과정의 배치·간격 변경은 사양 변경이 아닙니다. Worker의 node pull과 Pod 정책의 통제 지점을 구분합니다.
- 공유 폴더의 9월 발표/영상은 현행 검증 자료로 다시 이름 붙이지 않습니다. 정본 발행·조건부 종결은 새 Runtime PASS와 다릅니다.
- 외부 공개본에 공유 경로·계정번호·자격정보·개인 연락처·비공개 원본 로그를 복제하지 않습니다.

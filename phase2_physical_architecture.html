  1. 외부 진입 경로 ↗

    외부 사용자 HTTPS → IGW → Ingress LB(public_transport_a, external) → 워커의 Router Pod(TLS 종료) → transaction-api.

  2. DB 통신 경로 ↗

    거래 API만 기존 PostgreSQL 5432에 접근합니다. Worker private_a 서브넷 → Relay → IPsec → 교육장 VPN 게이트웨이 → DB 경로와 복귀 경로를 시험창에서 적용·원복합니다. 출발 /24 범위는 앱 정책·DB 인증·실행 증적으로 보완하며 엔진 DB 접근과 VPC 전체 허용은 금지합니다.

  3. 이미지 Pull ↗

    Worker가 Relay·IPsec·교육장 VPN 게이트웨이를 거쳐 Harbor 443에서 이미지를 내려받는 확정 설계입니다. 보안그룹·방화벽·복귀 경로, 전용 인증·strict TLS·cold-pull과 전환/복귀는 실환경 검증 대상입니다. ECR은 준비된 경우 NAT·IGW를 경유해 수동 전환하며 VPN·DB 복구를 대신하지 않습니다.

  4. 인터넷 Egress ↗

    private_a/b/c 0.0.0.0/0 → NAT GW(EIP fds-nat) → IGW → ECR·S3 등 리전 서비스. ECR/S3용 VPC Endpoint 없음. Relay EIP는 egress 우회 경로가 아님.

  5. 컨트롤플레인 연결 ↗

    Worker는 PrivateLink를 통해 Red Hat 관리 영역의 ROSA HCP 제어 영역에 연결합니다. 4.22.17 고정, Worker 단일 AZ 3대는 관리 제어 영역의 단일 AZ를 의미하지 않습니다. Runner는 공개 관리 API 443에 직접 접근하며 인증·CA·권한·동작 검증은 별도입니다.

적용 기준과 확인 범위

2차 설계 확정

docs-v3.1.22(2026-10-19)의 확정 설계입니다. 단일 가용영역은 Worker 배치 범위이며, 클라우드 통합 검증과 최종 인수는 별도입니다. 이번 변경은 도면의 표현·생성 방식을 통일한 것이며 실제 서버 시험을 새로 수행한 결과가 아닙니다.

3

확정 설계 (물리)

  • ROSA HCP · 공개 API/Ingress · Worker 단일 AZ 2a
  • Worker 3대 private_a · NAT 1개 공용 (private_b/c는 생성만, 미사용)
  • 진입: 인터넷 → IGW → Ingress LB → Router Pod · 출구: NAT → IGW
  • 이미지 공급안: Harbor Primary + ECR 수동 전환 (Runtime 대기)
  • machine 10.20.0.0/16 · pod 10.128.0.0/14 · svc 172.30.0.0/16
4

실환경 검증·보류 · 점선

  • 이미지 공급: Harbor 443의 허용·인증·cold-pull·전환/복귀 검증 별도
  • OADP → S3 백업은 보류 · 실제 복원 검증 없음
  • Runner 직접 배포 채택 · API 접속 경로·동작 확인 대기
  • 온프렘 경로는 승인된 시험창에서 적용·시험·원복. DB·Harbor 복귀 경로 각각 검증
  • VPCE·LB 개수: 생성 후 readback
5

그리지 않은 것

  • 추가 Hybrid DNS 보류 · public DNS/IP 및 엄격한 TLS 검증 유지
  • 계정번호·EIP·리소스 ID는 공유용으로 생략

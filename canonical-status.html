부팅 시 보호 전환, 일부 상태 확인(Probe)의 실제 실패→서비스 대상 제외→복구, 시간 동기화 장애·재부팅 복구 등은 원 판정과 재검토 조건을 유지합니다.

서비스·관측

일부 비정상 거래 입력, 운영 DB 제약, 전 구간 무손실·장시간 부하, edge HTTPS와 경보·관리 접근의 한계는 조건부 종결로 해소되지 않습니다.

자동화·자격정보

검증한 수동 호출과 부분 관측을 전체 자동화 호환성으로 확대하지 않습니다. 보호 보관·임시 예외의 담당·재검토 조건을 유지합니다.

이월

후속 구현 3건은 인계가 완료되었지만 구현은 To Do이며 확정 완료일은 없습니다. 인계 완료를 구현 완료로 표시하지 않습니다.

2차 확정 사양의 핵심

  • AWS EC2 Libreswan Relay 1대와 별도 NAT Gateway 1대를 사용합니다. Worker는 단일 가용영역의 m5.xlarge 3대이며, Red Hat 관리 제어 영역과 구분합니다.
  • ROSA HCP 4.22.17, 외부 공개 경로는 /api와 /readyz. Router에서 TLS를 종료한 뒤 앱까지는 HTTP입니다.
  • 거래 API만 기존 PostgreSQL에 접근합니다. 데이터 경로의 네트워크 출발 범위는 Worker 서브넷이며 앱 정책·DB 인증·실행 시점 증적으로 요청 주체를 추가 확인합니다.
  • Harbor가 주 이미지 저장소이고 ECR은 준비된 경우에만 수동 전환합니다. 자동 복제·자동 전환은 없으며 ECR은 VPN·DB 장애의 복구 수단이 아닙니다.
  • Worker의 이미지 다운로드와 Pod의 NetworkPolicy는 통제 지점이 다릅니다. TLS·인증·이미지 식별값 검증 실패 시 신규 배포를 중단하고 기존 정상 Pod를 보존합니다.
  • 배포 계정은 정해진 앱 객체만 변경합니다. Secret·권한·보안 정책·클러스터 전체 변경은 배포 경로에서 제외합니다.
  • VPN·DB 연결은 승인된 작업창에서 적용·시험·원복합니다. 설계 확정이 1차 서버의 영구 설정 변경을 승인하지 않습니다.
